# Plan 03-01: Deterministic Red-Flag Evaluation Engine & Emergency State Machine

## Objective
Establish the clinical triage evaluation engine that deterministically intercepts Level 4–5 red-flag symptoms in <1ms without network or LLM dependency, configure mobile telephony permissions and intents (`url_launcher`), and wire the emergency state machine and GoRouter `/emergency` navigation path.

<threat_model>
| Threat ID | STRIDE Category | Risk | Mitigation Strategy |
|---|---|---|---|
| **T-03-01** | Denial of Service / Bypass | Red-flag evaluator relies on slow LLM or network call, resulting in dropped or delayed emergency alerts during connectivity loss. | Evaluator is 100% deterministic, local, and synchronous (`RedFlagEvaluator`), executing in <1ms client-side with regex and structured categorical thresholds. |
| **T-03-02** | Tampering / False Negative | User inputs a colloquial or misspelled high-acuity symptom (e.g. "boca torta", "quero me matar", "crushing chest pain") that bypasses structural questionnaires. | Trilingual regex fast-gate inspects raw text inputs across `pt-BR`, `es`, and `en` with case/accent insensitivity. |
| **T-03-03** | Elevation of Privilege / Platform Crash | `url_launcher` attempts to dial emergency numbers on Android 11+ or iOS without manifest package visibility declarations, failing silently. | Explicitly declare `<queries>` with `android.intent.action.DIAL` and `tel` scheme in `AndroidManifest.xml` and `LSApplicationQueriesSchemes` in `Info.plist`. |
| **T-03-04** | Information Disclosure / State Pollution | Previous emergency session data or half-completed surveys linger in memory after emergency trigger. | Emergency controller triggers atomic teardown of active triage draft memory upon activation. |
</threat_model>

    1. Implement `mobile/lib/features/emergency/domain/red_flag_evaluator.dart`:
       - Include compiled trilingual `RegExp` patterns for `suicideRegex`, `strokeRegex`, `chestPainRegex`, `airwayRegex`, `thunderclapRegex` with case-insensitivity.
       - Implement `evaluateText`:
         - If text matches suicide pattern -> returns `EmergencyContext` with `suicidalCrisis`, `severityLevel: 5`, `isEmotional: true`.
         - If text matches chest pain pattern -> returns `EmergencyContext` with `chestPain`, `severityLevel: 5`, `isEmotional: false`.
         - If text matches stroke pattern -> returns `EmergencyContext` with `neurologicalStroke`, `severityLevel: 5`, `isEmotional: false`.
         - If text matches airway pattern -> returns `EmergencyContext` with `anaphylaxisAirway`, `severityLevel: 5`, `isEmotional: false`.
         - If text matches thunderclap pattern -> returns `EmergencyContext` with `thunderclapHeadache`, `severityLevel: 5`, `isEmotional: false`.
       - Implement `evaluateStructured`:
         - If `intensity == 5`: triggers `generalCriticalIntensity` (or specific organ category if mapped), `severityLevel: 5`.
         - If `intensity == 4`:
           - If physical and system is `cardiovascular_chest` -> `chestPain`
           - If physical and system is `respiratory` -> `respiratoryDistress`
           - If physical and system is `neurological` -> `neurologicalStroke`
           - If physical and system is `head_neck` -> `anaphylaxisAirway`
           - If emotional and dimension is `depressive_hopelessness` -> `suicidalCrisis`, `isEmotional: true`
           - If emotional and dimension is `anxious_agitation` -> `anxiousPanicCollapse`, `isEmotional: true`
           - If emotional and dimension is `stress_burnout` -> `severePsychosisDelirium`, `isEmotional: true`
         - Otherwise returns `null`.

       - Test negative controls: mild knee pain (intensity 2), mild stress (intensity 2), headache with intensity 3 -> all return `null`.
