# Plan 08-02: Network Connectivity Monitoring, Resilient Outbox Worker, and Offline UI State

**Phase:** 8 — Offline Caching & Outbox Synchronization  
**Plan:** 08-02  
**Requirements covered:** SYNC-01, I18N-01  
**Mode:** mvp  

---

## Goal

Complete the end-to-end offline check-in experience:
1. Monitor network connectivity changes in real-time.
2. Background outbox worker drains pending check-ins chronologically when online.
3. Handle offline triage submission gracefully: queue to outbox and deliver clinical guidance without network failure screens.
4. Non-intrusive offline status banner informatively displayed when disconnected.
5. Automated tests and live hot restart verification.

### T3 — Resilient Background Outbox Sync Worker
**File:** `mobile/lib/features/sync/presentation/controllers/sync_outbox_worker.dart` [NEW]
Worker listening to connectivity changes: when online, fetches pending outbox items and submits via `TriageOutcomeRemoteDataSource` with exponential retry backoff.

### T4 — Connect Outbox Enqueueing to Triage Flow
**Files:** `mobile/lib/features/triage_outcome/data/triage_outcome_remote_data_source.dart` [MODIFY], `mobile/lib/features/triage/presentation/screens/triage_wizard_screen.dart` [MODIFY]
When device is offline during Step 5 submission, persist to Drift outbox and return immediate clinical guidance without blocking user.

### T5 — Offline Status Banner Widget
**Files:** `mobile/lib/features/sync/presentation/widgets/offline_indicator_banner.dart` [NEW], `mobile/lib/features/home/presentation/screens/home_screen.dart` [MODIFY]
Display non-intrusive banner indicating offline status and pending sync item count.

### T6 — Automated Tests & Hot Restart
**File:** `mobile/test/features/sync/sync_outbox_worker_test.dart` [NEW]
Verify worker triggers on reconnection, processes items FIFO, and marks records synced. Run `flutter test` and hot restart.
