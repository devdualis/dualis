# Plan 01-01: NestJS 12 Fastify Bootstrap, Drizzle ORM Schema & PostgreSQL RLS Engine

## Objective
Establish the foundational backend walking skeleton using NestJS 12 and Fastify on Node.js 22 LTS, configure Drizzle ORM 0.45.2 with PostgreSQL 16/17 supporting Supabase (dev) and Google Cloud SQL São Paulo (prod), and implement native engine-level PostgreSQL Row-Level Security (RLS) with a transaction-scoped `withRls` execution runner to guarantee absolute tenant isolation under LGPD Art. 11 (SEC-01).

## Context
- Requirements: [SEC-01]
- Source of Truth: `.planning/phases/01-backend-foundation-postgresql-rls-data-encryption/01-RESEARCH.md` (Sections 1, 2, 3, 7, 8)
- Test Strategy: `.planning/phases/01-backend-foundation-postgresql-rls-data-encryption/01-VALIDATION.md` (Tasks 01-01-01 & 01-01-02)

<threat_model>
ASVS Level: 1 (Block on: high severity threats)

| Threat ID | Category (STRIDE) | ASVS Ref | Threat Description | Mitigation Strategy | Test Verification |
|-----------|-------------------|----------|--------------------|---------------------|-------------------|
| T-01-01 | Elevation of Privilege | V4.1 | Superuser bypass or unforced RLS allows database queries to view/modify symptom logs across tenant boundaries. | Enforce `ALTER TABLE symptom_logs FORCE ROW LEVEL SECURITY;` and `ALTER TABLE users FORCE ROW LEVEL SECURITY;`. Define PostgreSQL policies using `user_id = NULLIF(current_setting('app.current_user_id', true), '')::uuid`. | `backend/test/security/cross-tenant-rls.spec.ts` (Scenarios 1-4) |
| T-01-02 | Information Disclosure | V4.2 | Recycled database connections from the connection pool retain `app.current_user_id` session settings, leaking tenant context to subsequent unauthenticated or different-tenant queries. | Enforce scoped transaction runner `DatabaseService.withRls` using `SELECT set_config('app.current_user_id', $1, true)` where `is_local=true` forces PostgreSQL to automatically reset context at `COMMIT` or `ROLLBACK`. | `backend/test/security/cross-tenant-rls.spec.ts` (Scenarios 5 & 7) |
</threat_model>
