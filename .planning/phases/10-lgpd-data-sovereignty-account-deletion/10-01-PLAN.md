# Plan 10-01: Backend LGPD Data Sovereignty Services (Export Data & Permanent Account Deletion)

## Threat Model
| Threat | Mitigation |
|--------|------------|
| Unauthorized data export or account deletion | Strictly require `JwtAuthGuard` and re-verify password in `DELETE /v1/auth/account` |
| Orphaned clinical or personal data after deletion | Execute within transactional context under RLS with cascading foreign key deletion across all child tables |
| Cross-tenant leakage during export | Isolate queries to `app.current_user_id` session setting |

## Tasks

### Task 10-01-01: Implement LGPD Data Export & Deletion DTOs and Service Methods
- Implement `backend/src/modules/auth/dto/delete-account.dto.ts` validating confirmation password (`@IsString()`, `@MinLength(8)`).
- Implement `backend/src/modules/auth/dto/export-data.dto.ts` defining portable JSON export contract.
- Implement `exportUserData(userId: string)` in `AuthService`:
  - Queries `users`, `userDisclaimerConsents`, `symptomLogs`, `triageEmergencyEvents` under RLS.
  - Decrypts symptom narratives using `EncryptionService`.
  - Formats into structured legal export object with metadata.
- Implement `deleteUserAccount(userId: string, dto: DeleteAccountDto)` in `AuthService`:
  - Verifies user exists and password hash matches with `verifyPassword`.
  - Atomically deletes user row under RLS; verifies child records cascade.
- Expose `GET /v1/auth/export-data` and `DELETE /v1/auth/account` in `AuthController`.

### Task 10-01-02: Unit and E2E Tests for LGPD Data Sovereignty
- Implement `backend/test/unit/auth-data-sovereignty.service.spec.ts` testing export formatting and deletion password verification.
- Implement `backend/test/e2e/auth-data-sovereignty.e2e-spec.ts` verifying endpoints, 401 unauthenticated access, 400 invalid password, 200 export, and 200 account deletion.
- Verify tests pass.
